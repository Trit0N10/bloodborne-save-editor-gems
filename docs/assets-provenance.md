# Original artwork provenance

All 974 visual and web metadata assets in `docs/assets-inventory.json` are generated by `scripts/generate-artwork.mjs` using the Node standard library. The generator authors circles, polygons, lines, flat colors, gradients and abstract geometric marks; it imports no images, fonts, game screenshots, game symbols or save files. The new hexagon-and-diamond app mark is a generic shape composition. It was authored by Codex for this derivative publication. These project assets are distributed under GPL-3.0 together with the project.

`docs/assets-dimensions.json` records only upstream filenames and PNG dimensions from Noxde/Bloodborne-save-editor 0.10.0. Matching all 968 PNG dimensions preserves the established canvas geometry and dynamic paths. The generator never needs the upstream checkout: `node scripts/generate-artwork.mjs` reproduces the entire asset set from the committed metadata. `node scripts/generate-artwork.mjs --check` compares decoded pixels, dimensions and valid PNG/ICO/ICNS structure against the authored geometry, then checks the inventory using exact committed bytes. The two ICO files contain newly generated PNG payloads at 16, 32, 48, 64, 128 and 256 pixels; the ICNS contains 128, 256, 512 and 1024 pixel PNG payloads.

Item icons are abstract placeholders, not depictions of in-game objects. Color, gem shape and rating marks aid scanning; item names and numerical data identify items. Fonts come from the operating system; no font files are shipped. The publication also removes descriptive game-lore text from resource fields while retaining field names and identifiers.

The inventory includes 953 public PNGs, 15 desktop PNGs, two ICOs, one ICNS, one authored SVG and two generated web metadata files. Its SHA-256 list authenticates the exact committed asset bytes through `scripts/test-publication.mjs`. Raster pixels are reproducible across supported Node runtimes, while zlib may produce a different compressed byte stream. Check mode accepts this compression difference only when all decoded pixels, PNG headers and icon directory/type structure match. The stored assets and inventory are never rewritten by checks. `scripts/test-artwork-equivalence.mjs` demonstrates unequal compression bytes passing for PNG and embedded ICO/ICNS PNGs, and altered pixels or corrupt containers failing. SVG and web metadata still require exact byte identity.
