## 应该下载哪个文件？

在发布页的 **Assets** 中选择 `Bloodborne-Save-Editor-Gems-<版本>-windows-x64.zip`。完整解压，保持 `resources` 与 `Bloodborne Save Editor Gems.exe` 同级。

`-source.zip` 和 GitHub 自动提供的 **Source code** 是源码包，不包含可直接运行的程序。`SHA256SUMS.txt` 列出程序包与对应源码包的校验值。

## 运行程序需要安装什么？

发布版面向 Windows x64，需要 Microsoft Edge WebView2 Runtime。若未安装，可从[微软官网](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)下载。Rust、Node.js 和 C++ 构建工具用于编译源码，运行便携版无需安装这些工具。

若仍无法启动，反馈时请提供编辑器版本、Windows 版本和完整报错，并说明是否完整解压、是否安装了 WebView2 Runtime。

## 应该打开哪个存档文件？

打开**已解密的角色文件**，例如 `userdata0000`。`userdata0010` 是系统数据。本工具不提供主机存档解密功能，也不会自动选择游戏正在使用的存档目录。

请根据游戏、模拟器或移植版的配置找到存档位置。若有多套安装或多个存档副本，先确认游戏实际使用的是哪份角色文件。

## 为什么存档打不开？

先检查文件是否为已解密的角色存档，而非加密主机存档、ZIP 压缩包或系统数据。文件损坏或格式不受支持也可能导致读取失败。请记录完整报错，不要随意改动文件内容来绕过错误。

若确认正常的备份也打不开，可以[提交反馈](https://github.com/Trit0N10/bloodborne-save-editor-gems/issues/new/choose)，提供编辑器版本、文件名、存档来源和报错。不需要上传存档本身。

## 为什么添加血宝石会失败？

新增宝石会检查注册表布局，以及所选背包或仓库的实际可用容量。无法验证的布局，或不足以容纳指定数量的剩余空间，都会阻止操作。

根据报错判断原因：容量不足时，可以减少添加数量，或通过游戏内正常操作腾出空间；布局不受支持时，请反馈完整报错和存档来源。减少数量不能解决布局不受支持的问题。

## 为什么修改后游戏里没有变化？

界面中的修改在点击「保存存档」之前只保留在内存中。部分页面还需要先确认或应用修改。添加或删除宝石后，请关闭血宝石管理窗口，再点击主界面工具栏的「保存存档」。

编辑前退出游戏。确认输出文件是这套游戏实际使用的角色存档，或通过对应的存档流程导入。保存成功本身不能证明每项修改都能被游戏接受。

## 怎样恢复备份？

退出游戏并关闭编辑器。先把备份和修改后的文件复制到另一处，再通过游戏或模拟器的存档流程恢复确认正常的备份。

打开文件时会创建 `<输入文件>.bak`。例如，先把 `userdata0000.bak` 另存到安全位置，再复制一份并命名为 `userdata0000`，用于恢复。主机存档流程可能仍需通过相应工具加密并导入。

再次打开原文件可能覆盖 `.bak`，因此它未必还保留需要恢复的进度。请保留编辑前的独立备份；编辑器无法重新生成已经丢失的旧存档。

## 所有存档和游戏版本都测试过了吗？

没有。已通过构建、本地化、素材和部分基于合成数据的宝石测试，界面检查也使用合成数据。0.11.0 尚未完成真实存档和游戏内测试。具体范围见[测试说明](testing.md)与[验证记录](release-validation.json)，这两份技术文档目前为英语。
